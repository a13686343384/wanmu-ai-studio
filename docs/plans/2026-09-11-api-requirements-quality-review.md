## 2. 对原始需求的理解

你要求的是一条可以实际生产的流程：

**建档弹窗 → 大模型提取资产描述词（知道将使用哪个图片模型）→ 用户主动生成全部资产与妆造 → 各集进度按事实更新 → 拆分为镜组与分镜 → 大模型校验并处理问题 → 配置与生成段资产 → 默认引用可调整且真正参与生成 → 当前页显示按建档画幅排列的视频空框 → 单个或批量生成视频。**

贯穿全程有三条验收要求：所有反馈真实；所有生成遵守现有统一 API 配置；明确要求严格对齐的原型及三类资产卡面必须用实际结果验证。不能用“按钮存在”“存了一个 JSON”“提示词写了宫格”替代这些要求。

原文编号存在粘连，后半部分没有连续数字。为避免漏项或篡改编号，本报告独立编号 R01–R19；它们是验收单元，不是声称原文有 19 个编号。

## 3. 重点缺陷和对使用的影响

### 3.1 模型选择没有贯彻到执行，P1

证据：`src/services/ai/live-ai.service.ts:101` 从所有启用文本模型按 createdAt 倒序取通道；`:113` chatText 参数只有 system/user/options，无所选模型。各能力的 input.model 多用于 usage，而未决定执行通道。用户选 A，实际可以调用 B，且凭据鉴权、模板转换不一定走插件统一执行引擎。

图片/视频在 `:63` 精确按 ID 查找时漏 kind 条件，旧 ID 回退虽缓解报错，却不能保证“使用所选模型”。`ScriptDetailView.tsx:154/:184` 单镜和封面仍写死模型；`:288` 提取传入的图片模型没有成为批量出图配置。

验收要求：用两个可区分的受控服务验证选 A 只调用 A；无效/错误 kind 不得静默偷换；显式 auto 才使用默认；记录实际模型及来源。

### 3.2 引用看似保存，实际既会被覆盖又不参与生成，P1

证据：`SegmentDialogs.tsx:86` 每次打开重新做字符串匹配；`:139` 将一份 refs 写进每个镜头。原型图10写“只会替换原先用到错误引用的镜头”，底部还要求保留独立场景。当前代码与弹窗自己的“独立局部引用会保留”说明相反。

`api/storyboards/[id]/generate/route.ts:46` 拼 prompt 只读风格/镜头描述/动作/运镜/用户 prompt；不解析 generationParams.refs，也不加载所选角色、造型、场景和道具图片。`PATCH` 只鉴权分镜，没有校验引用资产归属和 costume→character 配对。后续接入引用消费之前必须补这一约束。

原型“用于1/2/3…镜”是本段内镜头使用范围，**不是跨集数量**。现有旧报告把它读成“用于 N 集”，应纠正。

验收要求：重新打开恢复保存值；只替换受影响镜头；独立场景保留；请求体包含真实引用素材；错误归属返回 400/404；批量写入全部成功或全部回滚。

### 3.3 大模型校验和生成门槛缺失，P1

证据：`StoryboardChecks.tsx:23–38` 是前端规则；`api/scripts/[id]/episodes/[episodeId]/storyboards/route.ts` 拆分后直接写表并标记完成，没有独立大模型校验。`StoryboardSection.tsx:217` 批量按钮仅依据有无分集禁用。

用户要求分析复杂场景、空空间、多人物调度和衔接；景别不同不能推出“视频延长”。目前展示“全部通过”只表示几个简单条件通过，无法表示符合原文校验。

验收要求：持久化大模型结构化报告与输入版本；修改镜头后报告过期；必须解决项阻断前后端生成；建议项提供具体处理或明确不适用原因。建议是否一律阻断存在原文歧义：推荐仅必须解决项硬阻断，建议显式处理/确认后继续，不能悄悄忽略。

### 3.4 段资产弹窗不是完整生产工具，P1

证据：`SegmentDialogs.tsx:440/:449` 双模型仅 auto；`:382–393` sequential 两支均 for-await；safeRewrite 只用于本地 Switch；`:503` 调度图和首帧图共用第一镜出图；`:523` 人群卡禁用。两个图块无论结果如何仍显示固定占位，未绑定独立产物。

图9明确描述：顺序模式后一张参考前一张；人群调度卡是文字方案，不是另一张图片。正确交付需要参数流、前图引用流、独立产物与后续视频消费，不能只增加按钮。

### 3.5 视频阶段实际顺序与原文不同，P1

`SplitStoryboardDialog.tsx:162` 拆分后立刻生成图片/视频，未经问题处理、引用调整；`ScriptDetailView.tsx:476` videoMode 是瞬态；`handleBatchVideo:227` 只生成有首帧图片的镜头；`live-ai.service.ts:751` 线上视频 invokeInput 没有消费 firstFrameUrl。

因此即使空框外观正确，仍可能遇到“还没调整引用已经生成”“完成后又显示图片”“缺首帧镜头被跳过”“首帧没有传给供应商”。这需要状态与请求链路一并修复。

## 4. 对昨晚交付质量的判断

- **有价值的完成部分**：新建弹窗、两步入口、四类批量出图入口、默认造型兜底、镜组字段/段卡、比例适配、部分预览、模型回退。
- **不能验收的关键部分**：模型选择一致性、引用保留及消费、LLM校验与门槛、段资产真实行为、视频阶段持久化、真实进度及失败反馈。
- **尚未取得证据的部分**：三类卡面真实出图；live 整链路；最新代码按图浏览器逐屏复核。

不继续使用旧报告的72%/75%：没有统一权重、样本和验收结果，这些数字无法复核。结论是“核心验收未通过，需返工后复验”，不等于所有工作无效。代码可以编译、旧 E2E 可以全绿，与本轮需求未完成并不矛盾。
